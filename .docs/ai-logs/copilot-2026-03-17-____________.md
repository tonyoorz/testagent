**User**
你看下谷歌的一个agent搭建建议：如何搭建一个数据分析agent
搭建一个数据分析 Agent（智能体）通常遵循 “感知-规划-行动” 的逻辑。核心在于让大模型（LLM）不仅能“说话”，还能通过编写和运行代码（如 Python）来处理数据。
以下是搭建的核心步骤：
1. 确定核心架构
一个标准的分析 Agent 由以下四部分组成：
大脑 (LLM)： 负责理解需求、拆解任务和生成代码（推荐 GPT-4o、Claude 3.5 Sonnet 等逻辑能力强的模型）。
规划器 (Planner)： 将复杂的分析需求（如“预测下季度销量”）拆解为数据清洗、描述性分析、建模等步骤。
工具箱 (Tools)： 最核心的是 Python 解释器（包含 Pandas, Matplotlib 等库），也可以包括数据库查询工具（SQL）。
记忆 (Memory)： 记录分析过程中的中间结果、变量含义和上下文。
2. 技术选型
你可以从现有的框架入手，避免从零开始造轮子：
LangChain / LangGraph： 灵活性高，适合构建复杂的多步分析流。
CrewAI： 适合让多个 Agent 协作（如一个负责清洗，一个负责画图）。
PandasAI： 专门为 DataFrame 交互设计的库，非常适合初学者。
OpenAI Assistants API： 自带 Code Interpreter，几行代码就能跑起来。
3. 核心搭建流程
环境配置： 搭建一个安全的 Sandbox（沙盒）环境供 Agent 运行 Python 代码。
提示词工程 (System Prompt)：
明确 Agent 的角色（“你是一个资深数据科学家”）。
告知其数据 Schema（表名、字段含义）。
设定约束（“输出必须包含可视化图表”、“如果出错请自动修复代码”）。
循环迭代 (ReAct 模式)：
Thinking: Agent 思考如何处理数据。
Acting: 生成 Python 代码并调用解释器执行。
Observation: 读取执行结果（如表格摘要或图片路径）。
Output: 将技术结果翻译成人类可读的业务洞察。
4. 关键挑战点
代码安全性： 必须限制 Agent 运行代码的权限，防止其访问系统敏感文件。
幻觉处理： LLM 可能会编造字段名，需要在 Prompt 中提供准确的数据字典。
大上下文： 当数据集很大时，不能把数据全塞给 LLM，只能传递 Metadata（元数据）。 跟我现在的框架来对比的话有什么借鉴的可以改进升级的地方
